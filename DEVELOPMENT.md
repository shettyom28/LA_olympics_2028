# EEN1037 Project Template

## Overview

<https://gitlab.computing.dcu.ie/een1037-2026/een1037-shared/een1037-2026-project-template>

This project folder contains a working template for a full-stack web application, with the
following features:

* Frontend: React SPA w/ Vite
* Backend: Django + Swagger/OpanAPI 3.0 REST APIs
* Websockets
* JSON Web Token authentication
* PostgreSQL Database
* Redis Cache + Message Queue
* Example microservice using pub/sub messaging & REST APIs
* Mailpit test SMTP server
* Minio S3-compatible Object Storage
* OTEL + Grafana-LGTM monitoring stack

To run on your local computer or server, simply run "docker-compose up". After the images are downloaded,
built and started, you can connect to the various endpoints of the stack as described below.

Optionally, you can extend this stack with extra services as necessary for your application, however that
won't be necessary to achieve all the project objectives.

To complete your EEN1037 Group Project, you will need to replace the example React & Django models, logic,
APIs, HTML, CSS & Javascript.

For a more complete webapp reference, you should read, check-out/download and run the full
example project "Book Reviews" website (a simple GoodReads clone) at:

<https://gitlab.computing.dcu.ie/een1037-2026/een1037-shared/een1037-2026-example-project>


## Building

How the stack is built and run is defined entirely through these files stored in git:
* [docker-compose.yml](docker-compose.yml)
* [docker-compose.monitoring.yml](docker-compose.monitoring.yml) (optional).


To build the stack:
```
docker-compose up --build
```

Stop and remove existing containers
```
docker-compose down -v
```

Stop and remove existing container + persistent volumes
```
docker-compose down -v
```


## Endpoints

- <http://localhost:8080> — Frontend (testuser:testpass)
- <http://localhost:8081> — Backend Django View (testuser:testpass)
- <http://localhost:8081/admin> — Django Admin UI (admin:admin)
- <http://localhost:8081/api/docs/> — Swagger/OpenAPI docs

- localhost:5432 — PostgreSQL (myappdb/myappdbuser:myappdbpass) (View with https://dbeaver.io/)
- localhost:6379 — Redis (myredispass) (View with https://redis.io/insight/)
- <http://localhost:8025> — Mailpit
- <http://localhost:9001> — MinIO Console (minioadmin:minioadmin)

If the `localhost` addresses are causing issues and timeouts (e.g. IPv6 or DNS issues), try `127.0.0.1`.


## Monitoring (optional)

Monitoring is covered using standard OpenTelemetry sent to the Grafana LGTM stack. You can use this to view the logs, metrics
and traces generated by various operations of your stack. However for day-to-day development
you shouldn't need this.

To start the stack with the monitoring services turned on:

```sh
docker-compose -f docker-compose.yml -f docker-compose.monitoring.yml up --build
```

Stop and remove existing containers
```
docker-compose -f docker-compose.yml -f docker-compose.monitoring.yml down
```

Stop and remove existing containers + persistent volumes
```
docker-compose -f docker-compose.yml -f docker-compose.monitoring.yml down -v
```

- <http://localhost:3000> — Grafana (admin/admin) — traces, metrics, and logs

Note the monitoring stack requires an additional 600MiB Memory.

To capture network traffic, you can use <https://www.wireshark.org> or `tcpdump` on the container host.
